# Currency and country reference tables (E-39/E-40)

These tables are static reference data. They help people search and enter codes; they do not change a transaction's currency, calculate tax, select an exchange rate or prove an entity's registration.

## ISO 4217 currency reference

`src/lib/isoCurrencyReference.ts` contains 179 distinct codes from the current SIX Group ISO 4217 List One, checked on **2026-10-23**: [SIX — Global Financial Data Standards](https://www.six-group.com/en/products-services/financial-information/market-reference-data/data-standards.html) and [SIX — current List One XML](https://www.six-group.com/dam/download/financial-information/data-center/iso-currrency/lists/list-one.xml). The list includes current fund, precious-metal, testing and no-currency codes as well as ordinary currencies. Recent codes `XCG`, `XAD` and `ZWG` are included; `ANG` and `BGN` are not current List One codes (Bulgaria uses EUR from 2026-01-01; BGN is historical). Existing stored codes are not rewritten.

`minorUnitDigits` follows the ISO minor-unit field. `0` is a real zero-decimal value (for example JPY); `null` represents ISO's `N.A.` and must not be read as zero. The table records numeric codes as three-character strings so leading zeroes are preserved. This reference is separate from `src/lib/currencyMinorUnits.ts`; its appearance in Settings does not alter the existing monetary conversion path.

ISO 4217 does not standardize display symbols. Where supplied, `symbol` is static display data copied from `currency-symbol-map@5.1.0` (BSD-2-Clause); symbols can vary by locale and may lag the maintenance list. A missing symbol is `null`; Settings → Currencies displays the alphabetic code rather than inventing one. The searchable table filters code, currency name and a known display symbol.

## ISO 3166-1 country reference

`src/lib/isoCountryReference.ts` contains 249 alpha-2, alpha-3 and numeric entries. The codes are compiled from `i18n-iso-countries@7.14.0` and checked against the assigned ISO 3166-1 set maintained by the [ISO 3166 Maintenance Agency](https://www.iso.org/iso-3166-country-codes.html). Its extra `XK` Kosovo row is intentionally excluded because XK is user-assigned, not an officially assigned ISO 3166-1 code. Numeric codes remain strings, including leading zeroes. English and Hebrew display names come from the package's locale data; where it supplies aliases, the table keeps the first (primary) label. The names are labels, not legal translations or tax authority determinations.

Settings → Tax profiles uses these codes as bilingual datalist suggestions for profile and registration countries. The field remains editable: suggestions do not reject legacy/non-ISO text, verify a registration, or decide tax treatment. The existing tax-profile validator still checks the two-uppercase-letter shape; it does not claim membership validation against this reference.

The static data has no country-table runtime dependency. Tests in `src/lib/isoCurrencyReference.test.ts` and `src/lib/isoCountryReference.test.ts` check row counts, uniqueness, sorting, lookup/search, symbols, leading-zero identifiers, decimal precision, the `N.A.` distinction, current additions and bilingual country labels. The existing Currency and Tax Profiles component tests check that the tables are reachable from their registered settings screens.
