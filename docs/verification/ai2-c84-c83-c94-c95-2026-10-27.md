## What this batch delivers

### C-95 — every total on the P&L, the balance sheet and the trial balance opens its entries

- New pure module `src/lib/statementDrill.ts`: `entriesForAccounts` and `statementTotalDrill` build
  the drill-down for a statement **total** from the accounts the total adds up. Only posted entries
  (`isPostable`) inside the total's own period, only lines touching those accounts, a duplicated
  account asked for once, and the figure on screen passed to the server explainer untouched (so the
  modal still says "these lines add up to X, not the Y shown" when the loaded history is partial).
  A group with no accounts opens nothing rather than an empty explanation.
- `ProfitAndLossView` — the revenue, expenditure and net-income cards each carry an **Entries**
  button (`See the entries behind <total>`); net income asks for income, cost of goods and expense
  accounts with the report's own sign, so the explained sum equals the card.
- `BalanceSheetReport` — **Entries** beside total assets, sub-total liabilities and sub-total equity,
  with a balance-as-of filter (no start date) and the statement's signs.
- `TrialBalanceView` — the footer's total debit and total credit are buttons: they open every account
  the trial balance adds up. They deliberately send **no** expected figure: a balanced trial balance's
  lines net to zero while its debit and credit totals do not, so a mismatch warning would be wrong.
- `Reports.tsx` — the shared drill handler now accepts a list of accounts and a label from a total,
  and keeps the account-name behaviour other reports already use.

### C-94 — a loading report shows the report's shape, not a spinner

- New `src/components/reporting/ReportSkeleton.tsx`: heading bars plus placeholder rows/columns,
  one polite `role="status"` with an `sr-only` label, the decoration `aria-hidden`, and
  `motion-reduce` respected.
- It replaces the spinner fallback in the report shell (`Reports.tsx`), so **every** registry report
  that is still loading shows it, and it also appears while `ReportPackDialog` reads the pack's
  sections — the slowest read in reports. The status text ("Reading all selected reports…") stays for
  screen readers.
- Limit, said plainly: the per-view "Loading report records…" statuses above report tables are
  unchanged. The queue row asked for the ten slowest reports; the shared shell covers all of them at
  first paint, but a view that fetches its own records still reports with text, not a skeleton.

### C-84 — the report pack carries the two reports the picker was missing

- `src/lib/reportPack.ts` gains `budget` ("Budget vs actual") and `stock` ("Stock on hand by age")
  sections built from the **existing** services `GET /api/v1/reports/budget-vs-actual` and
  `GET /api/v1/reports/stock-aging`. No new endpoint, no recalculation: each line is the service's own
  number, and the pack's month (`endDate`'s month) and as-of day (`endDate`) are exactly what it asks
  for.
- Budget rows keep budget / actual / variance per line with totals; over-budget lines are counted in a
  warning. Stock rows print units and value per item with a total, and warn when units came from
  before the stock history began. An empty month or no stock says so instead of printing an empty
  table, and a payload that does not match refuses to print rather than filling totals with zero.
- `ReportPackDialog` prints the month for the budget section and the as-of day for stock, with a cover
  line for each, and names the first column per section.

### C-83 — customer certificate reminders are drafted on the screen

- New `src/lib/tax/certificateReminder.ts`: a short English or Hebrew letter for a certificate that
  expired, expires within 30 days, or has no recorded expiry. It states what the records hold, asks
  for a current certificate, says it is a request and not a decision about the customer's tax status,
  and signs with the workspace name. A row that needs review (unreadable number or date) gets no
  letter: that is fixed on the customer. `mailto:` is built only when the customer has a saved email.
- New `src/components/reporting/CertificateReminderDrafts.tsx`, wired into Reports → **Customer tax
  certificates**: language switch (English / עברית), one draft per customer, copy to clipboard, and
  "Open in mail app" when there is an email. **Nothing is sent, filed or changed** — sending remains AI
  #1's email path, and the screen says so.

## Review round (PR #418 conversation, 27 Oct)

Every automated finding was read and each real one fixed in code, with a test:

| Finding (Codex / CodeRabbit) | What was wrong | Fix |
|---|---|---|
| Balance sheet: equity subtotal drill | the printed subtotal is `totalEquity + netIncome`, but the drill asked only equity accounts with `expectedCents = totalEquity` (and did nothing when there are no equity accounts) | it now sends the equity **and** the income/cost-of-goods/expense accounts and the printed subtotal, so the explainer adds up to the number beside the button |
| Balance sheet: liabilities on cash basis | on cash basis the server adds unapplied payments to `totalLiabilities` without a line, so the server's explanation could not equal the figure | on cash basis the three totals are disabled with a stated reason (switch to accrual), instead of opening a mismatched list |
| Trial balance: column totals | the explanation sums signed lines and shows a net, so a gross debit/credit column total looked "zero" | the totals say exactly what they open ("every posted line; this column totals gross debits, the lines net to zero because each entry balances") and still send no expected figure |
| Drill-down local fallback | the fallback listed each entry's whole `totalAmountCents` when the figure's name matched no account | `DrillDownModal` now sums the lines of the accounts the figure is made of, and says so above the list |
| P&L expense "Entries" control | white text on a light card in light mode | uses the shared theme-aware link colour |
| Reminder drafts keyed by name | two customers with one name shared a key and a copy state | drafts carry the customer record id; key and copy/failure state use it |
| Reminder drafts copy status | success/silence was not tied to the letter | status is per record, cleared when the language changes, and a refused clipboard is announced as an error |
| Reminder drafts after a stale customer read | a mail link could use an address from an invalidated snapshot | `emailsTrusted` (set from the confirmed read) — an unconfirmed list keeps the drafts to copy but builds no mail link, and says why |
| Report skeleton `aria-busy` | a busy live region can hold its own announcement back, and this component never clears it | `aria-busy` removed; the test now asserts its absence |
| Pack: empty selected section | an empty section was prepared and printing enabled with only a warning | preparing now refuses a selected section with no rows and names the reason |
| Pack: budget totals | the service repeats an account's whole monthly actual for each budget on it, so "Total actual" double-counted spending | totals are per **account**: its budgets add up, its spending counts once, variance follows; a warning says how many budgets span how many accounts |
| Pack: stock aging section | the age buckets the service returns were dropped, so "by age" printed no age | buckets, unknown-age units and oldest-unit days are printed as their own rows, adding nothing to the value total |
